# Джерело керування й сервісні параметри SU600 v1

09.10.2026: backend **0.53.0**, firmware **0.10.1**, Alembic head **0029**.
Реалізовано для поточного драйвера SU600. Приймання цих нових записів на фізичному
стенді ще відкрите. Інші SUSWE-моделі мають власні карти; наявність інструкції або
паспортного профілю не вмикає запис через SU600-драйвер.

## Доступні дії

| Хто | Де | Дія |
|---|---|---|
| Власник, адміністратор клієнта, оператор з `command.execute` | Пристрій → Панель | Місцеве / Дистанційне керування |
| Спостерігач | Панель | Перегляд прочитаного джерела без запису |
| `service_admin` у призначеному scope або `superadmin`, з `command.execute` і `capability.manage` | Адмін/сервісний сайт → пристрій → Обладнання | F0.10, F0.11 |

Службовий API повторно перевіряє поточні права, scope й MFA перед доставкою.
Адміністратор організації зі звичайним platform role `user` не може записувати
сервісні F-параметри. Кнопки не обходять серверну перевірку.

| SU600 | Регістр | Значення |
|---|---|---|
| F0.02, джерело RUN | `0x0002` | Місцеве: 0, панель; дистанційне: 2, зв'язок |
| F0.03, джерело частоти | `0x0003` | Місцеве: 0, потенціометр (крутилка) панелі; дистанційне: 6, зв'язок |
| F0.10, час розгону | `0x000A` | 0,1–999,9 с, один raw word = 0,1 с |
| F0.11, час гальмування | `0x000B` | 0,1–999,9 с, один raw word = 0,1 с |

Джерело: надана **SU-600-24.12.18.pdf**, таблиці F0 на PDF-сторінках 33–35
(друковані 13–14), Modbus на PDF-сторінці 23 (друкована 8).
Індекс параметра десятковий: F0.10 відповідає `000AH`, а не `0010H`.
Це перший дозволений набір редактора. Довільної адреси, запису захистів двигуна,
reset/autotune, параметрів RS-485, напрямку й меж частоти в цій версії немає.

## Правила запису

Потрібні Remote opt-in контролера (`CONTROL`, `EXTENDED_TEST`,
`REMOTE_OPERATION`), свіжі дані того самого boot session, чинний зв'язок/UTC/NVS,
правильна прив'язка, STOP, фактичні 0 Гц, відсутність аварії та активної програми.
Усі ввімкнені розклади перед записом мають бути призупинені. `DISARM` забороняє
ці дії до нового дозволеного сеансу. Стара firmware без `vfd_settings` нічого не записує.

Форма зберігає очікувані старі значення й окреме підтвердження. Сервер серіалізує
дії під Device lock; контролер перечитує стан і очікувані значення перед записом.
TTL стосується прийняття, а не тривалості роботи. Перед кожною операцією
перевіряються зупинка, строк дії та актуальний мережевий дозвіл.

Обидва переходи спочатку очищають стару команду зв'язку командою STOP `2000H=1`
та частоту `2001H=0`, вимагаючи правильних FC06 echo. При переході на сайт
контролер переводить F0.03 у 6, читає задану частоту 0 Гц і лише після цього
переводить F0.02 у 2. Зміна на
панель переводить F0.03 у 0 та F0.02 у 0. Обидва джерела перечитуються.
Команда RUN не надсилається. Для наступного запуску потрібна нова команда
після повторної перевірки дозволу; старий queued RUN не поновлюється.

Місцевий режим у цій версії означає **RUN/STOP кнопками панелі та частоту її крутилкою**, не клеми й не фізичний
селектор шафи. F0.02=1 не перехоплюється сайтом. В місцевому режимі зупинку
виконуйте на панелі/установці: сайт не гарантує пріоритет Modbus STOP над
місцевим джерелом. Поточна апаратна установка не має окремо прийнятого фізичного
Local/Remote-селектора; його узгодження — окреме завдання драйвера й монтажу.

F0.10/F0.11 записуються один раз, лише якщо прочитане значення збігається з
очікуваним. Після — незалежний FC03 readback. Загублений echo цього запису
може підтвердитися читанням; загублений echo підготовки STOP/zero забороняє
ввімкнення дистанційного джерела. Незмінене значення не записується повторно.
Зміна часу гальмування впливає на тривалість зупинки; чинні перевірки часу
переходів і захистів контролера залишаються.

## Невизначеність і журнал

`vfd.source.set` має `{source, expected_run_source, expected_frequency_source}`;
`vfd.parameter.set` має `{code, expected_raw, value_raw}`. Обидві дії проходять
через звичайний журнал MQTT v2/v3, sequence, TTL і equipment target.
Result містить прочитані `before_raw/actual_raw` або джерела та `write_attempted`.
Успіх означає прочитаний результат, не ACK.

0.10.1 обирає місцеву частоту від штатної крутилки (F0.03=0). Прочитаний
попередній варіант F0.03=1 показується як кнопки панелі; його можна окремо
перевести на крутилку. Телеметрія, графіки, журнал і дозволені сервісні
параметри зберігаються. Запуск, таймер, етапи й розклади із сайту потребують
повернення до дистанційного джерела; зміна джерела не поновлює розклади сама.

Перерваний перехід може залишити змішану пару джерел. Немає автоматичного
rollback або повторного запису: журнал показує фактичну пару, RUN блокується,
оператор оновлює дані й окремо підтверджує наступну дію. Після timeout HTTP UI
автоматично читає `/devices/{id}/commands/by-request/{request_id}`, не повторює POST.
Ручної кнопки «Перевірити результат» немає. Тимчасова відсутність квитанції
не припиняє GET-перевірку; опитування призупиняється у прихованому розділі
та без мережі. Знайдена квитанція перевіряється за пристроєм, автором і payload.
Статус `result_unknown` також опитується: пізній Result з'являється автоматично.
При відсутності підтвердження перевірте журнал і свіжі дані; не вважайте зміну
виконаною лише тому, що закрився діалог.

Сервер блокує інший запис/RUN під час незавершеної зміни. `result_unknown`
звільняється для нових дій лише за свіжим звітом того самого boot з sequence
не нижче зміни; STOP доступний. Це серіалізація окремих команд, а не повна
сервісна lease, bulk snapshot або вибіркове відновлення всіх параметрів етапу 4.

## Оновлення на наявному Windows-стенді

Спочатку зупиніть двигун і призупиніть розклади. Збережіть чинні `.env.*`,
`.local/` і приватні заголовки firmware. Оновіть checkout гілки
`codex/vfd-source-service`, потім у корені репозиторію:

```powershell
Set-Location 'C:\Users\seraf\Documents\TechBaza\techbaza-iot'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\update-vfd-service.ps1
```

Скрипт збирає новий backend, застосовує чинну міграцію та перезапускає API
клієнта/персоналу зі збереженими overlays. Він не створює нові акаунти,
не змінює tunnel/сертифікати чи прапорці керування й не очищає дані.
Вікно чинного Pinggy залишається відкритим. Якщо endpoint уже минув,
поновіть його за [V4-інструкцією](v4-lte-bench.md) окремо; адреса в firmware
має відповідати чинному tunnel.

В Arduino IDE відкрийте `firmware/kerumo_v3/kerumo_v3.ino` та завантажте **0.10.1**
з чинними `config.local.h`/`lte_config.local.h`. Не використовуйте `Erase All Flash`:
старий scoped/raw календарний журнал NVS мігрує зі збереженням sequence,
binding hash, історії та прапорця можливого руху. Недоставлений запис після
reboot позначається невідомим і не повторюється. Повертати стару firmware
після нових записів NVS слід лише за окремою процедурою сумісності.

Перезапустіть обидва frontend-процеси. У папці `frontend`:

```powershell
# Клієнтський сайт, окреме вікно
$env:NEXT_PUBLIC_PORTAL_MODE = 'customer'
$env:NEXT_PUBLIC_API_BASE_URL = 'http://127.0.0.1:8001'
npm.cmd run dev -- --port 3000
```

```powershell
# Адмін/сервісний сайт, інше вікно
$env:NEXT_PUBLIC_PORTAL_MODE = 'staff'
$env:NEXT_PUBLIC_API_BASE_URL = 'http://127.0.0.1:8002'
npm.cmd run dev -- --port 3001
```

Потрібна вже налаштована `.env.staff`; встановлення службового кабінету описане
в [staff-console-v1](staff-console-v1.md). Не запускайте reset demo для оновлення.

## Приймання VFD-SET-01 — відкрите

1. Перевірити firmware 0.10.1, LTE/MQTT, свіжі параметри й зупинку 0 Гц; порівняти
   F0.02/F0.03/F0.10/F0.11 з панеллю SU600 і зафіксувати модель/ревізію.
2. Призупинити розклади. Через customer ввімкнути панель; перевірити F0.02=0,
   F0.03=0, збереження телеметрії, заборону RUN із сайту, роботу RUN/STOP та крутилки панелі.
3. Зупинити на панелі. Повернути дистанційне керування: F0.02=2/F0.03=6,
   0 Гц навіть при ненульовому положенні крутилки, відсутність самозапуску. Задати допустиму частоту й окремо перевірити
   новий START/STOP за вже погодженими умовами стенда.
4. Сервісним акаунтом прочитати й записати один погоджений час розгону/гальмування;
   зіставити до/після на панелі й у журналі, потім за новим підтвердженням повернути
   початкове значення. Звичайний owner не має редактора й отримує API 403.
5. Перевірити stale, рух, fault, DISARM, ввімкнений розклад, інший інженер,
   зміну значення на панелі між підтвердженням/записом, загублений echo/result,
   живлення між двома джерелами та збереження NVS після оновлення.

Автоматичні тести перевіряють контролер із модельованою шиною, PostgreSQL/HTTP
та браузер. Вони не закривають фізичне приймання цих нових записів.
