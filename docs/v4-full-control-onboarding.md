# V4: від заводського комплекту до готової установки

Поточна реалізація: backend **0.56.0**, міграція **20261013_0033**,
firmware **0.12.1**. [Виправлення дефектів](v4-defect-fixes.md).
Виробник готує контролер і, за потреби, паспорт комплекту;
клієнт активує його у власному кабінеті й проходить
[первинний майстер власника](owner-guided-setup.md): автоматична перевірка,
відсутні дані, місцеве підтвердження й прийняття результату.
Звичайний помічник може підготувати чернетку через посилання на дві години
без службового акаунта. Окремий дозвіл сервісного працівника для цього
первинного шляху не потрібний. F/P-параметри залишаються у службовому кабінеті.

Наведений нижче службовий шлях із зареєстрованим монтажником збережено
для професійної підготовки та подальшого обслуговування. Таке запрошення
на об’єкт і тимчасове посилання первинному помічнику мають різні права.

Реалізація підтримує керування тільки з перевіреним драйвером для фактичної
повної моделі **SUSWE SU600A-5RG1-B**. Профіль залишається стендовим:
«Повне керування» не означає промислову сертифікацію, підтримку всіх SUSWE
або довільний запис F/P. Фізичне приймання нового заводського шляху
ESP32-S3/A7670E/SU600 із firmware 0.12.1 **ще відкрите**; цей документ
не підтверджує завантаження прошивки на конкретну плату.

## 1. Виробник готує комплект

У службовому кабінеті головний адміністратор із підтвердженим двоетапним
входом відкриває «Виробництво». Реєструє серійний номер, модель і ревізію
контролера, тип інтернету **4G (LTE)** та фактичний протокол заводської перевірки.

У «Комплект постачання» є два варіанти:

- **«Тільки контролер»**: паспорт і робочі межі внесе власник у первинному майстрі
  або допоможе підготувати помічник після встановлення.
- **«Контролер із частотником»**: виробник обирає SUSWE SU600, вносить
  повну модель зі шильдика, фактичні дані двигуна та робочі межі установки.
  Верхня межа не перевищує 50 Гц і номінальну частоту зазначеного двигуна.
  Потужність, струм і напругу не підставляють за припущенням. Без двигуна
  обирають відповідний варіант, а не вигадують його паспорт.

Вибір серії визначає сумісний драйвер за повною моделлю. Неперевірена модель
не стає сумісною від перейменування. Підготовлений паспорт можна додати
через «Підготувати паспорт обладнання» в реєстрі до першої конфігурації.
Після її створення зміни виконуються через сервіс обладнання.
Шаблон створює початковий паспорт і конфігурацію під час активації,
але не підтверджує монтаж і не надає дозвіл пуску.

Одразу після реєстрації збережіть і видайте комплект правильно:

| Матеріал | Призначення і кому передати |
|---|---|
| Один публічний QR на контролері | Постійне посилання `/connect/{id}` і серійний номер. Без паролів і ключів. |
| Закрита картка покупця | Серійний номер, одноразовий пароль активації; технічний розділ із мережею та унікальним паролем локального налаштування. Передати запечатаною покупцеві. Другого QR немає. |
| Приватний `factory-{serial}.json` | Заводський ключ і дані підготовки. Зберігати у виробника; не передавати покупцю й не публікувати в GitHub. |

Секрети видаються одноразово. Публічний QR можна розміщувати зовні упаковки;
людина, яка отримала закритий пароль, може активувати неприв’язаний контролер.
Запис постачання сам по собі не перевіряє факт продажу.

## 2. Виробник готує й завантажує Full-прошивку

Потрібні доступні через SIM стабільний публічний HTTPS customer API та
managed MQTT із довіреними сертифікатами. Адреса лише на localhost/LAN
і тимчасовий годинний Pinggy endpoint для заводського виробу не підходять.
[Сервер, шлюз і TLS](v4-factory-onboarding.md#сервер).
SIM, активний мобільний інтернет та APN готують до передачі комплекту.
Для листа монтажнику налаштуйте `STAFF_PUBLIC_URL` службового сайту.
Він має бути доступний фахівцю через передбачений VPN; звичайний клієнтський
`MAIL_PUBLIC_URL` не замінює службову адресу.

Запустіть Docker Desktop. Якщо локального образу генератора ще немає,
побудуйте його; це не запускає й не скидає базу даних:

```powershell
Set-Location 'C:\Users\seraf\Documents\TechBaza\techbaza-iot'
docker build --tag techbaza-demo-backend:local .\backend
if ($LASTEXITCODE -ne 0) { throw 'Не створено образ генератора' }
```

Мінімальна інтерактивна команда:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-factory-v4.ps1
if ($LASTEXITCODE -ne 0) { throw 'Комплект прошивки не підготовлено' }
```

Скрипт запитає шлях до приватного JSON, HTTPS origin, якщо його не можна
визначити з комплекту, і шляхи до довірених PEM CA для API та MQTT.
Генерація типово виконується через Docker без мережі; встановлювати Python
у Windows для цього не потрібно. Режим за замовчуванням — **Full**, APN —
`internet`. Якщо оператор використовує інший APN, задайте його явно:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-factory-v4.ps1 `
  -KitPath 'C:\private\factory-566787.json' `
  -ApiUrl 'https://app.example.com' `
  -CaPath 'C:\private\api-ca.pem' `
  -MqttCaPath 'C:\private\mqtt-ca.crt' `
  -Apn 'internet' `
  -ControlMode Full
if ($LASTEXITCODE -ne 0) { throw 'Комплект прошивки не підготовлено' }
```

Шляхи та домен у прикладі замініть фактичними. Скрипт друкує `READY` і
новий каталог `.local/factory-v4/{random}/kerumo_v3`. В Arduino IDE відкрийте
**саме цей** `kerumo_v3.ino` та завантажте у призначену плату ESP32-S3.
UART модема: TX4/RX5; UART RS-485 SU600: TX17/RX18. Не копіюйте старі
`*.local.h`, UID, MQTT-пароль чи manifest зі статичного стенда.
Існуючий каталог виводу не перезаписується; помилка генерації залишає
скетч із забороною компіляції, а не придатний до передачі частковий комплект.

Full вмикає підтримку ручних команд, таймера, етапів і розкладів у прошивці.
Реальний дозвіл використання приходить із сервера тільки після перевірки
установки. Для зміни такого дозволу сумісну Full-прошивку не перепрошивають.
Окремий `-ControlMode ReadOnly` потрібен лише для свідомо обмеженого комплекту;
таку стару/обмежену прошивку для повного керування потрібно оновити.

## 3. Клієнт активує обладнання

1. Сканує QR на контролері й входить зі своєю поштою та особистим паролем.
   Новий користувач підтверджує пошту, створює пароль і зберігає ключ відновлення.
   Для наступного контролера використовує той самий акаунт.
2. Вводить пароль активації із закритої картки й назву об’єкта або обирає
   наявний об’єкт. Типово використовується «Мій особистий кабінет»:
   сервер створить або повторно використає його робочий простір.
   Назва контролера, організація й часовий пояс доступні в додаткових параметрах.
3. Подає живлення на контролер і модем із підготовленою SIM та чекає.
   Домашній Wi-Fi для V4 не вводить. Сторінка автоматично оновлює готовність;
   повторна активація чи постійне натискання «Перевірити» не потрібні.
4. За потреби розкриває «Запросити монтажника» й вводить пошту вже
   зареєстрованого активного сервісного фахівця з підтвердженою поштою.

Запрошення доступне власнику/адміністратору з правом керувати учасниками.
Воно надає сервісний доступ тільки до об’єкта цього контролера на **7 днів**;
посилання потрібно прийняти протягом **3 днів**. Це scope об’єкта, а не лише
одного пристрою: інше обладнання цього самого об’єкта також входить до доступу.
Лист веде у службовий кабінет, де фахівець входить під своєю поштою з MFA.
Запрошення не надає незнайомій людині глобальну роль `service_admin`.
Якщо запис членства вже існує, права не перезаписуються — власник має
звірити його у списку учасників. [Ролі й службовий вхід](staff-console-v1.md).

Клієнт бачить готовність, показання та дозволені команди. Первинний паспорт,
робочі межі та прийняття підготовки доступні власнику в
[клієнтському майстрі](owner-guided-setup.md). Виробник або професійний
монтажник також можуть виконати службову підготовку нижче; подальші
технічні зміни залишаються у службовому кабінеті. Активація не змінює пароль особистого акаунта,
не надсилає RUN і не означає, що частотник уже перевірено.

## 4. Професійний монтажник завершує чотири кроки у службовому кабінеті

Монтажник входить у службовий сайт зі своїм акаунтом, двоетапним кодом та
чинним доступом до цього об’єкта. Приймає запрошення на призначену пошту;
відкриває пристрій → «Обладнання» → «Підготовка установки».
Сервер перевіряє platform роль `service_admin`/`superadmin`, scope і
`capability.manage` для кожної операції. Клієнтський owner не отримує
цього доступу лише від ролі власника.

1. **«Паспорт обладнання»**. Звірити підготовлений виробником паспорт
   зі справжніми шильдиками частотника й двигуна. Якщо комплект містив
   лише контролер, натиснути «Підготувати паспорт» і внести фактичні дані.
   Початкову помилку можна виправити до першої конфігурації; після неї
   використовувати захищену сервісну заміну.
2. **«Робочі межі»**. Перевірити або задати межі для установки через
   «Налаштувати робочі межі». Профіль і стандартна шина SU600 визначаються
   конфігурацією: адреса 1, 9600 baud, 8N1. Збереження не записує довільні
   F-коди й не замінює налаштування захисту двигуна. Дочекатися доставки
   конфігурації до контролера.
3. **«Підтвердження біля установки»**. Зупинити двигун, заблокувати пуск,
   перевірити підключення, захисти й незалежну зупинку. Утримувати BOOT
   **3 секунди**, підключити телефон до `KERUMO-{перші 8 символів id}`
   із паролем локального налаштування з картки. Відкрити
   `http://192.168.4.1` → «Підтвердити монтаж» → «Повернутися до налаштування»
   → «Завершити налаштування». Повернути телефон до інтернету й
   дочекатися в кабінеті підтвердження саме поточної конфігурації.
   Контролер перевіряє STOP, 0 Гц, відсутність fault і сумісний профіль;
   відповідь про прийнятий запит ще не є підтвердженням виконання.
4. **«Дозвіл використання»**. За свіжого підтвердження й зупинки натиснути
   «Дозволити використання». Обрати «Спостереження без керування»,
   «Стенд без двигуна · до 60 секунд» або
   «Повне керування після перевірки установки» та підтвердити перевірку.
   Останній режим потребує паспорта двигуна й Full-capability плати.
   Дочекатися «Готово до використання», а не лише «Дозвіл збережено».

Серверний дозвіл передається окремо від паспорта й має власну ревізію.
Він дійсний лише для поточної прив’язки, hash конфігурації та невідкликаного
доступу; плата повертає його прийняття в діагностиці. Кеш попереднього boot
не є дозволом. Не потрібно вручну вводити Serial ARM для звичайної роботи
цього Full-комплекту; свіжі UTC/мережа/сховище/STOP та апаратні guards залишаються.
Місцеве джерело SU600 — RUN/STOP і крутилка панелі; дистанційне — команди
зв’язку. Перемикання джерела є окремою підтвердженою дією після зупинки.

## Відновлення після місцевого блокування

Якщо серверний дозвіл уже збережено, але пуск навмисно заблоковано місцевим
DISARM, саме закриття локальної сторінки не прибирає блокування.
Монтажник біля зупиненої установки повторює BOOT 3 секунди, вхід у захищену
мережу та `http://192.168.4.1`. Натискає **«Дозволити керування після перевірки»**,
повертається до налаштування й натискає «Завершити налаштування».
Контролер ще раз перевіряє STOP і лише прибирає місцеве блокування;
чинний серверний дозвіл та підтверджений паспорт залишаються необхідними.

**Активація, підтвердження монтажу, дозвіл, його відновлення, reboot і повернення
4G не запускають двигун.** Для пуску потрібна нова явна команда користувача
або новий допустимий календарний запуск. Перервана програма не продовжується
від повернення мережі. Якщо дані застаріли, сайт не підтверджує фізичну зупинку.

## Обслуговування і передача іншому власнику

Щоб змінити вже чинний паспорт або межі, монтажник спочатку зупиняє
установку, призупиняє розклади й завершує очікувані команди. На місці
відкриває портал через BOOT 3 секунди, підключається до захищеної мережі
та `http://192.168.4.1`, потім натискає «Завершити налаштування»
**без** кнопки відновлення дозволу. Портал установлює місцевий DISARM;
його закриття саме по собі це блокування не прибирає.
Після повернення телефона до інтернету дочекатися свіжого STOP/0 Гц/DISARM
у службовому кабінеті, зберегти зміни й дочекатися доставки нової конфігурації.
Потім знову відкрити BOOT-портал, підтвердити монтаж для нових налаштувань,
завершити місцеве налаштування й виконати службове введення в роботу.
Для нового заводського комплекту ця початкова заборона вже діє.

«Оновити доступ контролера» змінює мережевий ключ та скасовує попередній
серверний дозвіл використання. Сервер створює нову ревізію наявного manifest
з новим hash, зберігаючи паспорт, межі та прив’язку. Стара телеметрія більше
не підтверджує поточну конфігурацію. Плата прив’язує місцеве підтвердження
також до UID та ревізії мережевого ключа. Монтажник повторно підтверджує установку
локально й виконує службове введення в роботу; повторний Serial ARM для
Full-комплекту не потрібний. Відкликання ключа без зв’язку не доводить,
що двигун фізично зупинився.

Передача зберігає публічний QR, але видає новий одноразовий пароль активації,
покоління й Device. Історія попереднього власника лишається його історією.
Підготовлений раніше заводський шаблон не переноситься: за час експлуатації
частотник або двигун могли замінити. Новий виробник/монтажник має підготувати
й підтвердити фактичний паспорт та знову дозволити використання.
Старий grant або кеш нового власника не авторизує.

## Перевірка перед передачею клієнту

На реальній установці зафіксувати версії й результати холодного старту без
USB/IDE, PPP→UTC→HTTPS→MQTT, одноразової активації, локального підтвердження,
видачі й прийняття дозволу, нового START/STOP, таймера/етапів/розкладів,
втрати 4G без самовідновлення та місцевого DISARM/відновлення без RUN.
Окремо перевірити відкликання й передачу власника без доступу попереднього.
Автоматичні backend/browser/native перевірки не закривають це фізичне приймання.
[Історичний LTE-стенд і незакриті питання](v4-lte-bench.md),
[поточний стан проекту](project-status.md).
