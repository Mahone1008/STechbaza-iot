# Панель, журнал і доступ до об’єктів

12.10.2026. Backend 0.53.0, schema 0029, firmware 0.10.1.
Міграція та нова прошивка для цих змін не потрібні.

## Панель і журнал

«Стан вибраної команди» знаходиться тільки в журналі. Панель залишає
короткий результат надсилання та перехід «Переглянути в журналі».
Деталі команди читаються лише за відкритого журналу; вибір зберігається
в адресі сторінки й не повторює команду після оновлення. Перехід фокусує
вибрану картку. Поточний стан обладнання залишається на панелі.

Спільні «Налаштування відображення» вирівняні по центру на ПК у вкладках
пристрою й каталогах. Мобільне компонування збережено.

## Доступ учасників

Форма «Додати учасника» типово пропонує лише перегляд вибраних об’єктів.
Поки не вибрано хоча б один об’єкт, запрошення недоступне. Можна вибрати
один або кілька об’єктів, до 100 згідно з чинним контрактом. Каталог
переглядається сторінками; назви вже призначених об’єктів читаються
на вимогу. Доступ до всієї організації обирається явно.

Одна роль діє на всі обрані об’єкти. Оператор може керувати обладнанням
у дозволених межах; сервісний учасник має дозволені налаштування.
Редактор F-параметрів залишається обмежений службовими ролями та чинними
серверними перевірками. Власник завжди має постійний загальний доступ.

Учасники й активні запрошення показують область доступу та строк.
Зміну прав існуючого учасника потрібно явно зберегти; зміна списку чи
поля не надсилає PATCH. Незмінний строк зберігається без округлення.
Форма надсилає лише змінені поля й час прочитаної версії доступу. Якщо
інший адміністратор уже змінив права, сервер відхиляє стару форму; вона
не відновлює об’єкти, які було відкликано під час редагування.
Сторонній запис учасника не перезаписується повторним запрошенням.
Для вже доданої людини потрібно відкрити «Налаштувати доступ».

У листі та на сторінці прийняття запрошення видно точні назви дозволених
об’єктів або загальний доступ, роль і строк. Metadata перевіряє чинність
посилання, права запрошувача, належність об’єктів та строк доступу.

Адміністратор, обмежений об’єктами, не читає й не змінює учасників
організації та не створює нові об’єкти. Read model прибирає ці permissions,
а mutation повторно перевіряє необмежений scope після блокування організації.
Сусідні об’єкти, їхні пристрої й дані залишаються закритими сервером.

## Перевірки та оновлення

Локально пройдено 137 frontend unit tests, typecheck, lint, format, перевірку
API й посилань; 57 тестів affected backend suites. Один сторонній MQTT-тест
залишається opt-in. Додано окрему регресійну перевірку сервісного запрошення:
лист, прийняття й права лише на обраний об’єкт.

Production builds клієнтського та службового сайтів і обидва bundle budgets
пройдено. Службовий browser-набір пройдено: 9 тестів. Повний клієнтський
набір та серверні integration checks виконуються також у GitHub Actions;
результати доступні в [PR №25](https://github.com/Mahone1008/STechbaza-iot/pull/25).

Перевірки охоплюють точний scope запрошення, збереження права/строку,
власника, звуження scope під час блокування, недоступність сусіднього
об’єкта, recipient metadata, desktop/mobile і командний журнал.

Оновити backend і обидва сайти за [чинними командами](staff-console-v1.md#запуск-двох-сайтів).
Існуючі memberships не змінюються автоматично: раніше наданий загальний
доступ залишається загальним, доки адміністратор явно не змінить його.
