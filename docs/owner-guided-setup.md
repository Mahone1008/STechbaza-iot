# Первинне налаштування власником і допомога без акаунта

13.10.2026. Backend **0.56.0**, schema head **0033**, firmware **0.12.1**.
Клієнт активує контролер у своєму особистому кабінеті,
перевіряє готовність і заповнює тільки відсутні дані. Для звичайного
первинного підключення окремий службовий акаунт монтажника не потрібний.
Виробник може заздалегідь підготувати паспорт комплекту; помічник може
допомогти з чернеткою через обмежене посилання. Результат приймає власник.

Це первинне введення конкретного контролера. Обслуговування вже введеної
установки, заміна обладнання та редактор F/P залишаються окремими
[службовими операціями](v4-full-control-onboarding.md).
Перевірений драйвер керування — тільки для фактичної повної моделі
**SUSWE SU600A-5RG1-B**. Новий шлях не додає драйверів інших серій або
повного сервісного редактора параметрів.

## 1. Від активації до готовності

1. Скануйте постійний QR, увійдіть або створіть особистий акаунт.
   Введіть одноразовий пароль із закритої картки й оберіть об’єкт.
   Оптовик не реєструє покупця; знати його заздалегідь не потрібно.
2. Увімкніть контролер і модем із підготовленою SIM. Сторінка `/connect/{id}` перевіряє
   зв’язок та готовність автоматично. Домашній Wi-Fi для V4 не потрібний.
3. Перегляньте паспорт і результати перевірок. Для підготовленого комплекту
   дані вже заповнені. Для окремого контролера внесіть відсутню модель,
   дані двигуна зі шильдика та допустимі робочі межі.
4. Натисніть «Зберегти дані», перевірте запропоновані дані й окремо
   натисніть «Підтвердити дані установки». Дочекайтеся доставки поточної конфігурації до плати.
   Якщо підготовлена конфігурація вже відповідає паспорту, повторно
   застосовувати її не потрібно.
5. За потреби підтвердьте фактичний монтаж біля зупиненої установки.
   Після свіжого підтвердження власник приймає результат і завершує
   первинну підготовку кнопкою «Прийняти установку» у своєму кабінеті.
   Для свідомого завершення тільки з показаннями є «Завершити для спостереження».
6. Для керування дочекайтеся прийняття дозволу платою. Пуск виконується окремою
   підтвердженою командою на панелі.

Збереження чернетки, застосування конфігурації, завершення налаштування,
повернення мережі й перезапуск не надсилають RUN. Припинена програма
сама не продовжується.

| Стан | Що підтверджено |
|---|---|
| **Активовано** | Контролер належить цьому об’єкту та акаунту. |
| **Підключено** | Надходять актуальні дані контролера. Збережений контакт у минулому не підтверджує поточний зв’язок. |
| **Готово** | Завершено перевірки для обраного режиму. Для керування плата також має прийняти чинний дозвіл. |

Для свідомо обмеженого режиму спостереження готовність означає доступ до
показань, а не дозвіл керувати двигуном. При втраті свіжих показань сайт
пояснює проблему й не видає останній відомий STOP за поточну фізичну зупинку.

## 2. Паспорт і чернетка

Укажіть фактичну повну модель частотника, а не його серійний номер.
Доступний профіль і межі залежать від сумісності цієї моделі. Дані двигуна
переписують зі шильдика; невідомі потужність, струм і напруга не підставляються.
Для повного керування з двигуном потрібні його номінальні частота,
потужність, струм, напруга та допустимі межі установки. Профіль SU600 не дозволяє верхню межу понад 50 Гц або
номінальну частоту зазначеного двигуна.

Неповну чернетку можна зберегти. Якщо частота двигуна, модель і межі
вже придатні для конфігурації, відсутні струм, напруга чи потужність
не змушують вигадувати дані: після перевірок власник може свідомо
завершити лише спостереження. Керування з двигуном залишається закритим.

Чернетка зберігає підготовлені дані для перегляду власником. Вона сама
не змінює застосовану конфігурацію й не дає дозволу керування.
Перед застосуванням власник звіряє дані зі шильдиком. Вибір серії
не доводить модель і не прошиває плату.

Форми фіксують покоління прив’язки, ревізію мережевого ключа, конфігурації
та чернетки. Якщо ці дані змінилися під час редагування, старе підтвердження
відхиляється. Оновіть стан і перегляньте актуальні дані; повторний запис
не виконується автоматично. Одночасна робота власника й помічника не
повинна мовчки перезаписувати чужі зміни.

## 3. Помічник на дві години

Власник може відкрити той самий майстер на своєму телефоні разом із
людиною, яка допомагає з монтажем, або створити тимчасове посилання.
Пароль особистого акаунта передавати не потрібно. Посилання діє
**2 години** за серверним часом і лише для первинної підготовки
**одного контролера** в його поточній прив’язці.

На сторінці підключення натисніть «Створити посилання для помічника», а потім
«Копіювати посилання». Помічник відкриває `/setup-help`; секрет передається
у fragment посилання, прибирається з адреси та зберігається тільки в пам’яті
поточної вкладки. Збережіть видану власнику копію для передавання помічнику.
Посилання є секретом цього тимчасового доступу, його не публікують.
Створення нового посилання відкликає попереднє; виданий секрет не
показується повторно у списку. Власник бачить строк і стан посилання.

Помічник без реєстрації бачить необхідні дані обладнання та перевірки,
заповнює чернетку й натискає «Передати дані власнику». Він не застосовує
конфігурацію й не завершує введення в роботу. Власник переглядає
результат, застосовує погоджені дані та приймає підготовку сам.

Посилання не дає доступу до інших пристроїв об’єкта, історії, звичайного
керування, F/P-редактора, передачі власника, мережевих ключів чи учасників.
Обмеження перевіряє сервер для кожного запиту.
Власник може відкликати посилання кнопкою «Відкликати посилання»; прострочена або відкликана відкрита
сторінка більше не зберігає змін. Зміна прив’язки чи мережевого ключа
та завершення первинної підготовки також припиняють цей доступ.
Якщо доступ власника відкликано або його повноваження змінилися,
помічник також втрачає доступ.
Підтвердження даних власником закриває посилання також тоді, коли
чернетка повністю збігається з уже збереженою конфігурацією й нова
ревізія не потрібна. Після прийняття даних помічник не може змінити
цю чернетку старим посиланням.

Це інший доступ, ніж [запрошення сервісного спеціаліста](v4-full-control-onboarding.md):
професійний сервіс входить зі своїм акаунтом і MFA та отримує явно
надані права на об’єкт. Тимчасовий помічник не стає учасником організації
і не отримує службову роль.

## 4. Підтвердження біля установки й прийняття власником

Перед підтвердженням зупиніть двигун, заблокуйте пуск і перевірте монтаж,
захисти та незалежну зупинку. Утримуйте BOOT **3 секунди**, підключіть
телефон до захищеної локальної мережі контролера й відкрийте
`http://192.168.4.1`. Пароль локального налаштування міститься в закритій
картці та відрізняється від пароля акаунта.

Натисніть «Підтвердити монтаж», завершіть місцеве налаштування й поверніть
телефон до інтернету. Для V4 ця тимчасова Wi-Fi-мережа потрібна для
місцевої перевірки; інтернет контролер отримує через SIM.

Після появи підтвердження власник звіряє результат на сайті й завершує
первинну підготовку. Сервер повторно перевіряє права, поточну прив’язку,
конфігурацію, свіжу зупинку та доступний режим прошивки. Для повного
керування потрібні чотири номінальні дані двигуна та Full-capability плати.
Поки плата не підтвердила чинний дозвіл керування, сайт показує очікування.

Якщо власник обирає «Завершити для спостереження», результат дозволяє
лише перегляд показань. Первинний майстер закривається так само;
додавання керування пізніше виконується через професійний сервіс.
Це свідомий вибір власника, а не автоматична заміна непідтвердженого
повного керування режимом спостереження.

Заводський паспорт скорочує введення даних, але не замінює підтвердження
монтажу. Правильність силового підключення й захистів не доводиться
галочкою або успішним читанням Modbus.

## 5. Після завершення

Первинні зміни та видача посилання доступні чинному власнику організації
зі звичайним клієнтським акаунтом і необмеженим доступом. Адміністратор
об’єкта, оператор, спостерігач або службовий акаунт не стають власником
через цей майстер. Права повторно перевіряються перед записом.

Первинний майстер закривається для цієї прив’язки. Ротація ключа,
обслуговування або відновлення не відкривають його повторно як спосіб
змінити вже введене обладнання. Використовуйте чинні процедури сервісу,
заміни, відновлення доступу чи передачі власника.

Редактор F/P залишається на службовому сайті. Заповнення людського
паспорта власником не дає права записувати параметри захисту, зв’язку
або інші службові регістри. Повний модельний каталог, сервісна сесія,
snapshot і вибіркове відновлення залишаються наступним етапом.

## 6. Перевірка й оновлення

Оновіть backend і обидва сайти, застосуйте нові міграції за
[чинним порядком запуску](staff-console-v1.md). Дані та вже введені
установки не скидаються. Сумісну Full-прошивку для додавання цього
клієнтського майстра повторно не завантажують.

У pilot-розгортанні з окремими DB roles після `alembic upgrade head`
повторно виконайте `python -m app.tools.install_runtime_roles --rules /rules/runtime-roles.sql`
за [інструкцією встановлення](staff-pilot-deployment.md#перше-встановлення).
Канонічні [правила runtime-доступу](../infrastructure/staff/runtime-roles.sql)
надають потрібні права на нові таблиці чернеток і посилань.
Саме оновлення схеми не замінює цей крок для вже наявних runtime roles;
паролі беруться з чинного приватного environment.

Після відновлення резервної копії застосуйте чинну
[recovery policy](backup-restore-v1.md#5-безпечний-запуск-відновленої-копії)
до повернення доступу й доставки команд. Вона відкликає всі відновлені
посилання помічників, зокрема видані ще до першого bootstrap плати.
Стара резервна копія не повинна відновити раніше відкликану допомогу;
за потреби власник створює нове посилання після перевірки відновленого стану.

Для програмного приймання перевіряють готовий і непідготовлений комплект,
чернетку без зміни конфігурації, окреме застосування й прийняття власником,
права різних ролей, межі доступу помічника, двогодинний строк, відкликання,
одночасні зміни, F5, прострочені дані, вузький екран і клавіатуру.
Локально пройшли 377 backend-тестів без пропусків із PostgreSQL/MQTT,
зокрема повторний повний прогін у Docker, і 12 перевірок службового API.
RLS-сценарії працюють у власних тимчасових БД та не залишають політик
у джерелі резервної копії. Перевірено міграції `0031 → 0033 → 0031 → 0033`,
Ruff, поточний mypy gate, OpenAPI/TypeScript і посилання документації.
Frontend: 164 unit-тести, 8 перевірок tooling та 11 нових Chromium-сценаріїв
майстра; знімки екрана перевірено на ширинах 320 і 1440 px.

Фізичне приймання нового шляху ESP32-S3/A7670E/SU600 залишається відкритим:
потрібні холодний старт без USB/IDE, реальні показання через LTE,
доставка конфігурації, місцеве підтвердження, прийняття дозволу,
новий START/STOP, переривання зв’язку без самозапуску та передача власника.
Software/API fixtures не замінюють ці результати.
