# Аудит форм KERUMO — 02.10.2026

База змін: `9a6d07537c1f1d55ea8143d545599b6527b72a78`. Обсяг — frontend:
поля дати, випадаючі списки, діалоги й мобільна геометрія. Backend 0.43.0,
firmware V3 0.5.0 та схема `20261001_0020` не змінені.

## Докази й причина повторення

Переглянуто три надані скриншоти від 02.10:

- `051827`: системний календар `<input type="date">` виходить за правий край
  Chrome Device Mode. Попередня заміна полів часу не змінювала поля дати.
- `051925`: фільтр повідомлень відкриває велике системне меню. Попередні
  стилі select діяли лише в перелічених контейнерах керування/історії;
  повідомлення, аварії та UI kit до цього переліку не входили.
  Заголовок «Контролер перезапустився» також дробився на літери.
- `051514`: Serial показує MQTT/TLS connection, але SU600 `read=0`,
  `profile=0`, `config=0`, `ready=0`, readings `MISSING`, ARM=0 і
  `last_stop=configuration_mismatch`. Це окремий стан контролера/VFD;
  скриншот не встановлює причину відсутності читання. UI-зміни не є його
  усуненням і не підтверджують фізичну готовність розкладу.

Попереднє виправлення було неповним: воно охоплювало конкретні екрани,
а не всі екземпляри спільних полів.

## Що змінено

- `DateField` замінює всі три системні date inputs редактора розкладу:
  початок, завершення повторення включно та винятки. Ввід ДД.ММ.РРРР,
  восьми цифр або вставленої ISO-дати; до API йде YYYY-MM-DD.
- `DatePicker` показує український календар у modal dialog: місяць/рік,
  поточний і вибраний день, попередній/наступний місяць, «Сьогодні»,
  «Скасувати». Розмір обмежений viewport; на низькому екрані прокрутка
  відбувається всередині діалогу.
- Перевіряються реальні календарні дати, високосні роки, межі 2000–2199,
  обов'язковість і завершення не раніше початку. Невалідна чернетка
  залишається доступною для виправлення, але не проходить submit.
  Відкриття календаря з датою поза діапазоном не ламає навігацію.
- «Сьогодні» використовує timezone об'єкта; календарна арифметика працює
  через UTC без зміщення дня через часовий пояс браузера чи DST.
- Стрілки переміщують день/тиждень, Home/End — межі тижня, Page Up/Down —
  місяць, Shift + Page Up/Down — рік. Enter вибирає день; Escape закриває
  календар без зміни чернетки. Фокус повертається до кнопки відкриття.
- Спільний `ModalDialog` обслуговує календар і наявні підтвердження:
  native modal/inert, доступні назва/опис, початковий фокус і Tab containment.
  Враховано queued `close` під час dev Strict Mode setup/cleanup, щоб
  повторне відкриття не закривалося застарілою подією.
- CSS для `appearance: base-select` перенесено на весь `.select`:
  повідомлення, аварії, історія, автооновлення, режими, розклади та UI kit.
  Прямі select історії замінено на `SelectField`; інші браузери зберігають
  native fallback. На вузьких екранах поля мають шрифт 16 px.
- Фільтри отримали достатню гнучку ширину, а основні заголовки таблиць —
  читабельну мінімальну ширину. Звичайні слова не дробляться на літери;
  широкі таблиці зберігають локальну горизонтальну прокрутку.

Клавіатурна модель звірена з
[WAI-ARIA date picker dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/).
Автоматичний axe не замінює перевірку фізичними assistive technologies.

## Якість коду й навантаження

Виправлення належать спільним компонентам, а не повторюваним умовам для
окремих сторінок. Чиста календарна арифметика відокремлена від API й React;
наявний експорт `calendarDate` з API-модуля збережено для сумісності.
Повторювану schedule fixture винесено в один тестовий модуль.

Нових залежностей, HTTP-запитів або фонових таймерів не додано. Календар
обчислює 42 дні тільки при рендері відкритого діалогу; він входить до
відкладено завантажуваного редактора розкладу. Ці зміни не додають роботи
контролеру. Чинні polling intervals і пауза hidden/offline/manual збережені.
Максимум календарного запуску — 7 діб; таймер/етапи — до 24 год.

Це перевірене покращення конкретного frontend, а не приймання всіх фізичних
сценаріїв або production-навантаження. `UI-01`, `PROGRAM-01`, `SCHEDULE-01`
залишаються в [реєстрі стану](project-status.md). Залишок ручного frontend
приймання — у [roadmap](frontend-roadmap-v1.md).
