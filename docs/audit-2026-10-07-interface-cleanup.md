# Аудит коду й упорядкування клієнтського інтерфейсу

Дата: 07.10.2026. База: `fa452c9`, після скасування загального перемикача
ручного/календарного режиму. Backend/OpenAPI лишаються 0.52.0,
Alembic head `20261007_0029`, firmware V3 0.8.1. Контракти та схема БД не змінені.

## Обсяг перевірки

Інвентаризація всього репозиторію: 717 tracked файлів на початку роботи.
Перевірено точки запуску обох API, Next.js routes/proxy, імпорти клієнтського й
службового інтерфейсів, Python definitions, CSS, package/lock файли,
PowerShell/CLI/CI entry points, firmware includes, міграції та інструкції запуску.
У `backend/app` 203 файли, `frontend/src` 154, firmware 27, scripts 36.

Для frontend виконані Knip 5 та TypeScript із `noUnusedLocals` і
`noUnusedParameters`; для Python Vulture зі звіренням кандидатів вручну,
Ruff і наявний scoped Mypy. Пошук CSS враховував статичні та складені назви
класів. Імпортний граф сам по собі не визначає безпечність видалення:
FastAPI routes, ORM attributes, Paho callbacks, CLI й native driver hooks
викликаються фреймворками або зовнішніми інструментами.

## Видалено або закрито від зовнішнього використання

- Не викликаний `_parse_datetime` з `backend/app/tools/command_e2e_simulator.py`.
- 18 назв класів старих списків, alarm/summary cards, toolbar та попереднього
  групування показників. Зі спільних CSS selectors прибрано лише мертву частину;
  чинні metric cards, badges, навігація та preview-компоненти збережені.
- 15 не використаних зовні експортів типів. Типи, потрібні всередині модулів,
  залишені приватними; прибрано зайві re-exports auth-session.

Не знайдено зайвих runtime npm dependencies чи не досяжних frontend modules.
Knip позначає Prettier як кандидат: він викликається через `spawnSync` із
`node_modules/prettier/bin/prettier.cjs` у `scripts/check-format.mjs`, тому його
потрібно зберегти. Production-only scan не є підставою видаляти tooling/tests.

Документація й тести збережені. Історичні міграції, SQLite journal compatibility,
backup recovery, CLI для стенда та preview fixtures залишені: вони забезпечують
оновлення встановлених систем і перевірки. Видалення історичних міграцій не
є очищенням невикористаного runtime-коду.

## Інтерфейс

- У головних діях сторінки об’єктів розміщені «Учасники організації» з чинною
  перевіркою `membership.read`. Оновлення списку знаходиться у згортуваному блоці.
- «Оновити панель» перенесено в «Налаштування відображення», поруч із вибором
  автооновлення. Списки, зв’язок, історія, розклади, паспорт і стан доступу
  мають компактні блоки оновлення; при помилці відповідний блок розкривається.
  Повтор завантаження та критичні стани/STOP не сховані.
- Показники на широкому екрані: задана/вихідна частота, струм/вихідна напруга,
  код помилки/стан роботи. На телефоні порядок той самий, одна колонка.
  Інші підтримувані датчики й додаткові показники залишаються доступними.
- У розкладах і діях із контролером додано відступи між поясненнями, станом і
  кнопками. На вузькому екрані операції доступу розташовані вертикально.
- Пояснення скорочені зі збереженням часових поясів, статусів та наслідків дій.
  Передача контролера більше не обіцяє обов’язкову 2FA: особистий обліковий
  запис та необов’язковий двоетапний вхід відповідають чинній моделі.

## Графік

Стиль та колір збережені. Додано сітку, часові підписи в часовому поясі об’єкта,
адаптацію SVG до фактичної ширини, вибір інтервалу мишею/дотиком/клавіатурним
повзунком. Для вибраного інтервалу показані середнє, мінімум, максимум і якість.
Таблиця повних даних лишається доступною. Відсутні значення не підміняються
нулем і не з’єднуються лінією. Час графіка означає час надходження даних на сервер.

Періоди: 15/30 хвилин, 1/3/6/12/24 години, 2/3/7 днів. Типовий період
залишився 1 година; збережені вподобання перевіряються й відновлюються.
Межі API збережені: до 7 діб, 1000 інтервалів, 100000 повідомлень.
Довший період при великому потоці може вимагати вибору коротшого періоду;
це повідомляється користувачу. Великі скінченні значення нормалізуються перед
побудовою координат, щоб уникати overflow; нуль і сталі показання зберігаються.

## Перевірки

- Backend: 305 тестів із PostgreSQL/MQTT, без пропусків. Нестабільний тест
  тижневого запуску отримав явний `now`, щоб час проходження suite не
  скорочував віртуальну тривалість. Runtime поведінка не змінена.
- Frontend: TypeScript, ESLint, форматування, unit/component/tooling tests,
  customer/staff production builds та budgets.
- Browser: збережені регресії входу, tenant isolation, команд, розкладів,
  stale/offline/429, історії, прокрутки й accessibility; додані перевірки порядку
  показників, header actions, відступів, UTC periods, клавіатури та touch графіка.
- Вузькі й широкі viewport, native dropdown popovers, WCAG Axe, відсутність
  переповнення всієї сторінки. Фізичний Android та SU600 цим прогоном не перевірені.
- Перевірка актуальності generated reference, локальних документаційних
  посилань і hash каталогу обладнання; dependency vulnerability gate.

Це перевірка реалізації й очищення підтверджених залишків коду, не фізичне
приймання стенда або зовнішній penetration test. Публікація виконується після
успішних CI перевірок поточного commit.
