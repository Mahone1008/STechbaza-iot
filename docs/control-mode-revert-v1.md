# Повернення попереднього керування розкладами

07.10.2026, backend **0.52.0**, міграція **20261007_0029**.

За уточненням замовника скасовано зміни PR #18: загальний перемикач
«Ручне керування / За розкладом» видалено з панелі та розкладів,
його API та блокування команд також видалено. Розклади знову працюють
за власним станом «Увімкнено / Призупинено». Ручні Start/STOP не змінюють
цей стан. Новий розклад вмикається після підтвердження «Зберегти та
увімкнути», як і до PR #18. Пропущені календарні запуски не виконуються
заднім числом.

«Місцеве / Дистанційне» означає джерело команд частотника: його панель
або контролер і сайт. Скасований перемикач цього не реалізовував.
Реалізацію джерела керування зараз відкладено за проханням замовника;
план залишається в [етапі 3](next-stage-plan-vfd-service-qr.md).

Для оновлення застосовуйте звичайний
[запуск службового стенда](staff-console-v1.md) **без `-ResetExisting`**,
потім перезапустіть frontend. Дані облікових записів, права, паролі,
об'єкти, обладнання, розклади та історія команд зберігаються.

Міграція 0028 залишається в історії для баз, які вже встановили 0.51.0.
Міграція 0029 прибирає лише п'ять службових полів скасованого перемикача
та його дві constraints. Підтримуються оновлення 0027 → 0028 → 0029
і 0028 → 0029; вручну виконувати `alembic downgrade` не потрібно.
Downgrade до 0028 відновлює структуру таблиць і вибирає календарний режим
для пристроїв з увімкненими розкладами, але не відновлює видалені значення
скасованого перемикача. Backup 0.50.0 та 0.51.0 зберігають сумісність.

Прошивка V3 **0.8.1** у цьому поверненні не змінюється.
