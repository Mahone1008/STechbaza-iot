# Спільне оновлення даних у клієнтському кабінеті

Стан: 08.10.2026. Backend/OpenAPI 0.52.0, Alembic head 0029 та firmware V3
0.8.1 збережені. Зміна стосується інтерфейсу й ручних GET-запитів.

## Де знаходяться дії

На сторінці пристрою ручне оновлення зібране в «Налаштування відображення»,
поряд із вибором автооновлення. Окремих блоків «Оновлення даних»,
«Оновлення історії» та «Оновлення зв’язку» всередині цих вкладок немає.

На вкладці «Панель» одна кнопка «Оновити панель» перевіряє показання й
видиму вибрану команду. В інших вкладках вона перевіряє панель пристрою,
а сусідня «Оновити дані» оновлює вміст поточного розділу:

| Вкладка | Дані для ручного оновлення |
| --- | --- |
| Графіки | Обраний показник, період та інтервал |
| Розклади | Список розкладів і відкрита історія запусків |
| Журнал | Поточна сторінка команд, вибрана команда та відфільтровані події |
| Обладнання | Паспорт та стан доступу, якщо його перегляд відкрито |

Організації, об’єкти й список пристроїв мають той самий блок налаштувань
з однією кнопкою «Оновити дані». Для пристроїв оновлення списку запускає
нову перевірку зв’язку; додаткового паралельного проходу availability немає.
Кнопка недоступна до завершення завантаження списку й перевірок зв’язку.

## Поведінка та обмеження

- Обрані показник, період, інтервал, фільтр подій, сторінка журналу,
  відкриті подробиці та чернетки залишаються на місці.
- Ручне оновлення не відкриває іншу вкладку й не повертає журнал на першу
  сторінку. Геометрія завантаження зберігає місце під користувачем.
- Приховані вкладки не додають свої запити до спільної дії. Після зміни
  користувача, сесії, організації чи пристрою набір дій створюється заново.
- Для вкладок кнопка використовує чинні query refresh callbacks: права, offline/hidden,
  один активний запит і Retry-After бюджети не обходяться.
- При помилці видимого джерела блок налаштувань розкривається. Помилка
  лишається біля відповідних даних; успішний повтор не згортає налаштування.
- Запуск, STOP, підтвердження операцій і повідомлення про блокування
  керування залишаються доступними у своєму розділі.

## Перевірка

Browser-регресії перевіряють склад GET-запитів після відвідування всіх вкладок,
відкритий/закритий доступ контролера, відсутність повторних availability
запитів, збереження періоду/таблиці й cursor журналу. Наявні перевірки
offline, 429, foreign/revoked даних, команд, розкладів і прокрутки збережені.
Спільний блок перевіряється на 320/393/768/1280 px та Axe WCAG.

Локальні TypeScript/lint/format/unit/build/budget і browser перевірки
доповнюються CI з реальним API/MQTT. Фізичний Android та SU600 потребують
окремого приймання. Оновлення не потребує reset облікових записів чи прошивки.
