# Повторний аудит розкладу й історії — 02.10.2026

База: `32288b380f9e0d78d3714f16d669982c549ca33f`.
Десять скриншотів користувача `052448`–`054624` показують попередній UI.
Ці зміни доповнюють [виправлення календаря та select](audit-2026-10-02-frontend-forms.md).

## Виявлене та виправлене

| Спостереження | Причина та результат |
|---|---|
| Пояснення режиму на `052448` | На самому знімку обрано «За таймером», а виділений текст описує одну частоту й відлік після її досягнення. Підміна календарним описом цим знімком не підтверджена. Пояснення тепер починається з назви актуального режиму; перемикання всіх чотирьох режимів перевірене browser tests. |
| Російський popup на `052711` | Це native constraint validation мовою браузера. Спільний `TextField` та `DateField` тепер показують українську помилку в сторінці, скасовуючи лише системний popup. Некоректний submit залишається заблокованим. Підказки про межі поля зберігаються поруч із помилкою. |
| `6:00` відхилено на `052739` | Попередній pattern вимагав дві цифри години. Приймаються H:MM, HH:MM та 3/4 цифри; API отримує HH:MM. Три цифри нормалізуються після завершення вводу, щоб не заважати набору чотирьох. |
| Помилка частот на `052845` / `052900` | Запуск 02.10 19:00–19:30, зміна 06:00 наступного дня — після STOP. Відмова правильна. Форма перевіряє конкретну зміну до POST і пояснює її час відносно запуску/зупинки або попередньої зміни. Виправлення пов'язаного поля прибирає помилку. |
| «До списку розкладів» веде нижче на `053534` / `053542` | Великий редактор вилучався без відновлення позиції. Після явного переходу фокус і scroll повертаються до заголовка списку; порожній список також має видиму точку повернення. |
| Стиснуті кнопки у винятках на `054507` | Додаткові секції отримали окремий контейнер, проміжки між рядками, оформлення винятку та роздільник перед фінальними діями. |
| Постійна біла область на `054035` / `054624` | `StableRegion` навколо історії безумовно зберігав найбільшу висоту, а keyed дочірній компонент закривав таблицю після зміни фільтра. Резерв тепер керується станом запиту й звільняється після відповіді або помилки. |
| Графіка «Струм» немає при 648 повідомленнях | На знімку 0 валідних вимірювань. Наявність повідомлень не означає числове значення цієї метрики. Додано пояснення missing/invalid; нулі не підставляються. Відсутній графік більше не залишає старої площі. |

Серверні перевірки, ролі, підтвердження запуску та апаратні захисти не змінені.
З API-повідомлень прибрано лише технічний префікс `Value error,`; зміст помилки
зберігається. Часові обмеження UI відповідають серверному локальному інтервалу:
1 хв–7 діб, до семи хронологічних змін; DST, перетини й права перевіряє сервер.

## Поведінка історії

- При зміні метрики, періоду або інтервалу попередній набір приховується.
  На час запиту геометрія зберігається; після відповіді показано актуальний
  компактний результат, таблиця початково закрита.
- При refresh тих самих фільтрів графік і відкрита таблиця залишаються
  на місці, поруч із кнопкою показано стан оновлення. Після відповіді дані
  оновлюються в поточному представленні.
- Помилка, зокрема відмова доступу, приховує попередні дані. Після завершення
  запиту зайва висота не утримується. При зменшенні документа біля самого
  кінця сторінки браузер може обмежити scroll її новою довжиною.
- Порожній період без повідомлень і повідомлення з missing/invalid значеннями
  мають різні пояснення. Таблиця якості залишається доступною в обох випадках.

## Перевірки та межі

- Unit: **120 PASS**, включно з коротким часом, неповним вводом, північчю,
  хвилинними межами, сімома добами, порядком переходів і нормалізацією payload.
- Production build / TypeScript / ESLint: PASS. OpenAPI: PASS, 0.43.0 / 51 paths.
- Bundle budget: PASS, 25 chunks; 291 558 / 358 400 bytes gzip,
  найбільший 71 628 / 122 880. Приріст від бази — 4 080 bytes gzip.
- ESLint перевіряє вихідний код і тести; з обходу виключено лише генеровані
  `playwright-report` / `test-results`, щоб повторний lint після browser tests
  не перевіряв сторонній мінімізований JavaScript переглядача trace.
- Повний production browser regression: **210 PASS за 7,6 хв**, без повторів.
- Окремо через `npm run dev`: 6 PASS, включно з коротким часом,
  хронологією змін, відступами, поверненням і missing-струмом.
- Переглянуто desktop/mobile screenshots винятків, повернення до порожнього
  списку й порожньої історії; перевіряються також наявний календар та режими.
- Нові сценарії запускають форму з locale `ru-RU`: системний invalid popup
  скасовано, український текст доступний через опис поля, invalid POST відсутній.
  Є перевірка виправлення пов'язаної дати/часу, фокуса у згорнутій секції та axe.
- Регресії історії перевіряють усі три фільтри на 320/1280 px, відкриту таблицю
  під час refresh, missing-струм із 648 повідомленнями та помилки API.

Локальний runtime — Chromium 153 через тимчасову конфігурацію поза репозиторієм,
як у попередньому аудиті. Фізичні Safari/iPhone, assistive technologies,
реальне навантаження й фізичний календарний запуск цим не приймаються.

Нових залежностей, HTTP-запитів або періодичних таймерів не додано.
Загальні поля та чиста часова валідація мають окремі модулі; виправлення
історії використовує чинний `StableRegion`, без нового механізму polling.
Статус фізичного `SCHEDULE-01` і решти ручного приймання — у
[реєстрі](project-status.md) та [roadmap](frontend-roadmap-v1.md).
