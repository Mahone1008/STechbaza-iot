## Результат

`/devices/{UUID}` читає один `GET /api/v1/devices/{id}/overview` після
перевірки device → site → organization → access. Окремого availability
запиту для цієї панелі немає. Backend 0.38.0 / 47 paths та міграції незмінні.

Панель будується за `modules[].channels`, а не за жорстким набором датчиків:

| Контракт | Віджет |
|---|---|
| `values / number` | Числове показання, одиниця з API, якість |
| `state / boolean` | «Так» / «Ні», `false` зберігається |
| `state / integer` | Точне безпечне ціле, включно з `0` |
| Невідомий тип каналу | Явне повідомлення про непідтримуваний тип |
| `supported=false` | Призначений модуль із поясненням відсутності підтримки |
| Command-only | Модуль керування без вимірювальних каналів |
| Порожній склад | «Для пристрою немає увімкнених модулів» |

Відомі ключі мають українські назви; невідомий числовий канал використовує
власний ключ і unit, без вигаданого фізичного призначення. Один assignment
не прирівнюється до окремого фізичного датчика чи RS-485 адреси.

## Межа довіри

Runtime parser перевіряє device/site/organization/UID, read permissions,
унікальність assignments і каналів, відповідність capability/module,
типи boolean/integer/finite number, unit та якість показань. Сторонні readings,
яким не відповідає призначений канал, відхиляються. Непідтримувані типи не
приводяться до number/boolean. У cache потрапляє тільки перевірена display
проєкція; сирі `snapshot` і `config` не використовуються для побудови віджетів.

Помилки API мають власний error/retry state, без demo fallback. Query key
містить user, auth session, device, organization і site. Зміна маршруту та
logout скасовують запити й очищують session cache; `gcTime=0` видаляє
неактивний overview. Старі показання приховано вже під час нового запиту.
