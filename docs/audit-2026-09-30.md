# Аудит документації та коду — 30.09.2026

База: `237458482459ecc65a58d1e83cb217bdf99a43df` після досьє V3 control.
Аудит охоплює inventory всього tracked tree, звірення чинних контрактів/
runbooks/plans із реалізацією, focused review критичних потоків і автоматичні
перевірки. Це не незалежна сертифікація безпеки й не доказ відсутності всіх дефектів.
[Актуальний реєстр стану й відкритих питань](project-status.md).

## Обсяг та метод

На базовій ревізії: **473 tracked files**, із них **102 Markdown**
(26 208 рядків). Синтаксично перевірено 190 Python files. Перевірено локальні
Markdown file links, версії/міграції, OpenAPI, channel/permission registries,
активні інструкції, статуси планів і попередні acceptance records.

Поглиблений перегляд: auth/session recovery й tenant guards, створення/
idempotency/dispatch/Stop/ACK/Result, telemetry ordering/quality,
restore quarantine, frontend polling/journal, firmware protocol/core/NVS
та SU600 profile. Inventory і автоматичні перевірки охоплюють усе дерево;
ручний семантичний перегляд зосереджений на цих потоках, а не на кожному
рядку generated schemas, lockfiles та історичних досьє.

Наявні історичні migrations, fixtures для tests/simulator та досьє з доказами
збережено. Їх не видаляють лише через вік. Runtime secrets/build outputs у
перевіреному tracked manifest не знайдено; це не аудит усієї Git-історії на secrets.

## Що закрито, а що залишається

Закриті A01–A10 у межах описаних змін. Окремо в документації враховано вже
завершені V3 read/control/repeat-start та gateway/DISARM/ESP power-stop checks.
Це не нове фізичне приймання під час аудиту.

Відкриті питання мають стабільні ID у [project-status](project-status.md):
V3-01 Offline без встановленої причини; V3-02 fault/soak; V3-03 latched E485;
V3-04 hardware protection; UI-01 manual acceptance; PROD-01–03 production;
CODE-01 quality/dependency gates; NEXT-01 майбутні функції; V4-01 4G.

За перевіреними потоками не встановлено нового критичного runtime-дефекту.
Це обмежений висновок цього огляду, а не гарантія. Архітектура має сильну
тестовану основу, але «топовий commercial product по всіх стандартах» ще
не доведений: немає завершених production deployment/OTA/fleet lifecycle,
незалежного security assessment, load/soak та польового acceptance.
Backend dependency ranges/transitives не зафіксовані lockfile; окремого
Python dependency audit/lint/type CI gate немає. Frontend npm audit gate
не замінює ці перевірки й не сертифікує hardware/network/application security.
