# Активація без реєстрації та аудит використання файлів

05.10.2026; backend 0.47.0, міграція `20261005_0024`, firmware 0.7.0.
Чинний [контракт доступу](buyer-onboarding-v1.md) і [ручне приймання](stage2-acceptance.md).

## Зміни доступу

Початок — заводські логін/пароль або публічний QR із паролем закритої
етикетки. Окремої реєстрації користувачів немає. Майстер створює персональний
TOTP/recovery комплект; браузер генерує постійний пароль через Web Crypto.
Покупець зберігає реквізити до claim і підтверджує код із застосунку.
Пароль, 2FA та прив'язка пристрою активуються однією транзакцією.
Заводський пароль не можна повторно використати як постійний.

Під час передачі змінюються покоління і комплект активації, очищується
посилання контролера на попереднього покупця. Новий власник створює власні
постійні реквізити та 2FA. Особистий акаунт попереднього власника з його
MFA та старою історією зберігається; доступу до нового Device він не має.

Зміна постійного пароля потребує старого пароля та свіжого TOTP і завершує
інші сесії. Міграція не скидає паролі/TOTP чинних користувачів. Виправлено
версію head у fingerprint резервного відновлення; 0.46.0/0023 bundles
лишилися у таблиці сумісності backup.

## Аудит файлів

Переглянуто inventory усіх 632 tracked файлів вихідної ревізії:
імпорти backend, точки запуску CLI, frontend imports/exports/dependencies,
Next routes, CI, Compose, скрипти, firmware includes і посилання документації.
Для TypeScript додатково використано Knip 6.39.0; до залежностей проєкту
цей інструмент не додано. Python AST-перевірка показала, що модулі без
імпортів запускаються як CLI з CI, Compose або інструкцій експлуатації.

Видалено:

- сторінку і компонент відкритої реєстрації; recovery винесено в окремий
  компонент, без signup API/DTO/service;
- застарілий `check-stage9-op2.ps1`, на який немає посилань і який дублював
  наявні frontend перевірки. Чинний запуск — через [приймання етапу 2](stage2-acceptance.md),
  frontend npm scripts та `scripts/check-stage9-op4.ps1`;
- невикористовувані demo alarms і їхні типи;
- зайві публічні exports/re-exports там, де функція або тип використовується
  лише всередині модуля; невикористані Python imports.

Документи збережено, інструкції відкритої реєстрації прибрано. Міграції,
CLI, UI-kit, tests та конфігурації з автоматичним завантаженням збережено
за їхнім призначенням. `prettier`, позначений Knip як unused devDependency,
фактично запускається `frontend/scripts/check-format.mjs`; його видалення
зламало б чинний quality gate. Після очищення Knip не знаходить unused
файлів або exports. Автоматичний пошук сам по собі не доводить відсутність
зовнішнього використання CLI; такі файли звірено з точками запуску.

## Перевірки

- 57 backend tests: factory login/QR, неправильні докази, одноразовість,
  атомарна активація MFA, конкурентний перший вхід, ідемпотентний claim,
  зміна пароля, recovery, scope, передача/історія, reset, browser cookies,
  equipment та backup compatibility.
- 4 PostgreSQL restore tests після оновлення перевірки head.
- Upgrade чистої БД і окремий цикл 0023 → 0024 зі старими password/TOTP
  та неприв'язаним комплектом: секрети збережено, логін комплекту додано.
- Ruff, mypy, TypeScript, ESLint, format gate, OpenAPI contract.
- 124 frontend unit tests та 8 перевірок tooling; production build і budget.
- 14 Chromium сценаріїв onboarding/передачі на фінальній збірці;
  також пройдено 17 сценаріїв входу й доступності.
- Генерований довідник, посилання Markdown і equipment profile hash.

Browser сценарії onboarding використовують mocked API; транзакції перевірені
окремо реальним PostgreSQL через HTTP-шар. Фізичні ESP32/VFD ці перевірки
не запускають. SIGMA додано лише для паспорта; керування потребує окремого
документованого драйвера. Прийнятий драйвер SU600 не змінювався.
